## Research focus

I study how to find vulnerabilities that automated tools struggle to analyze, and how AI agents can make security analysis more effective without introducing new security risks.

- **Program analysis:** uncovering injection vulnerabilities and business-logic flaws in web applications and software packages, especially when dynamic language behavior or application state makes analysis difficult. My work includes static analysis, abstract interpretation, code property graphs, and fuzzing.
- **Agentic security:** both using agents for security analysis and studying the security of agentic systems. I work on agents that assist static and dynamic analysis, generate and validate tests, and discover vulnerabilities. I also study how these systems can be misled or exploited, and how evaluation can distinguish reliable capabilities from behavior dependent on conversational context or recognizable benchmark tasks.

## Research and publications

### CoBrA — PHP vulnerability discovery

- Publication: **CoBrA: Context-, Branch-sensitive Static Analysis for Detecting Taint-style Vulnerabilities in PHP Web Applications**.
- Venue and status: ICSE 2026; published.
- Authors: Yichao Xu, Mingqing Kang, Neil Thimmaiah, Rigel Gjomemo, V. N. Venkatakrishnan, Yinzhi Cao.
- My contribution: first author and lead engineer; designed and built the Kotlin static analyzer for PHP applications.
- Problem: dynamic PHP features, including dynamically constructed function calls, make it difficult to resolve program behavior and track unsafe flows of untrusted input.
- Method: context- and branch-sensitive static analysis, using an abstract domain graph and a stretch-relax algorithm to resolve dynamic behavior and analyze taint propagation across functions.
- Results: the evaluation found **54 previously unknown vulnerabilities in 19 real-world applications**, with **9 CVE identifiers assigned**, as reported in the paper.
- Benchmark results: 88.66% detection of known vulnerabilities with a false-positive rate below 0.3% on the PHP tarpits benchmark. These rates describe that benchmark, not all PHP applications.
- Research period: May 2023–Mar 2025, Johns Hopkins University SecLab.
- Paper: https://dl.acm.org/doi/10.1145/3744916.3773195
- PDF: https://www.yinzhicao.org/COBRA/cobra.pdf
- Code and datasets: https://github.com/jhu-seclab-cobra

### FAST — scalable JavaScript vulnerability analysis

- Publication: **Scaling JavaScript Abstract Interpretation to Detect and Exploit Node.js Taint-style Vulnerability**.
- Venue and status: IEEE Symposium on Security and Privacy, 2023; published.
- Authors: Mingqing Kang, Yichao Xu, Song Li, Rigel Gjomemo, Jianwei Hou, V. N. Venkatakrishnan, Yinzhi Cao.
- My contribution: second author; implemented JavaScript abstract interpretation and led the evaluation, including reproducing 4 prior analyzers and building comparison and debugging utilities.
- Problem: JavaScript's dynamic behavior makes accurate analysis expensive, while scalable approximations can miss vulnerabilities or produce inaccurate results.
- Method: bottom-up abstract interpretation resolves dynamic call relationships; top-down interpretation follows relevant paths, prunes unrelated statements, and checks constraints to assess exploitability.
- Results: the study found **242 previously unknown vulnerabilities in npm packages**, with **21 CVE identifiers assigned**. These are results of the collaborative study.
- Research period: May 2021–Nov 2022, Johns Hopkins University SecLab.
- Paper: https://ieeexplore.ieee.org/document/10179352
- PDF: https://www.yinzhicao.org/FAST/ODGen-FAST.pdf
- Code: https://github.com/fast-sp-2023/fast

### AnonVul — evaluating vulnerability-discovery agents

- Publication: **Discovery or Memorization? A Faithful Benchmark for Real-World Business-Logic Vulnerability Discovery**.
- Status: arXiv preprint, 2026.
- Authors: Rui Yang, Yichao Xu, Zhuohao Zhang, Jiahao Ji, Chaowei Xiao, Yinzhi Cao, Ziyang Li.

### cpg2py

- A Python library for loading code property graphs exported by Joern and querying their nodes and relationships.
- Minimal example, after installing `cpg2py` and supplying exported `nodes.csv` and `rels.csv` files:

```python
from pathlib import Path
from cpg2py import cpg_graph

graph = cpg_graph(Path("nodes.csv"), Path("rels.csv"))
for node in graph.nodes(lambda n: n.type == "Function"):
    print(node.name)
```

- Repository: https://github.com/samhsu-dev/cpg2py

## CoBrA interactive explanation on the website

- The homepage includes a collapsed teaching example adapted from CoBrA's Emoncms example. It illustrates the method with predefined code and graph states.
- **Phase I — Dependency Generation:** local abstract interpretation records dependencies within each function; context-dependent values remain unresolved in the abstract domain graph.
- **Phase II — Call Paths Generation:** lightweight interpretation uses calling contexts to resolve dynamic calls and construct candidate paths from untrusted input to sensitive operations.
- **Phase III — Vulnerabilities Detection:** more detailed interpretation checks branch conditions and data flows along candidate paths, removing infeasible candidates and identifying surviving taint flows.
- Visitors can compare feed and admin calling contexts. The reduced example illustrates how `get_engine(0)` eventually selects `MySqlEngine` over `OtherSqlEngine`.
- This is an interactive explanation of a published method. It does not execute PHP, SQL, or the CoBrA analyzer.
